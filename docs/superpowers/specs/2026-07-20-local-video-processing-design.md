# Fully Local Video Processing Design

**Date:** 2026-07-20

**Project:** Video Content Capture (`vcc`)

**Status:** Approved design; implementation planning pending
**Primary source:** `視野環球財經robots_07-19-2026 22-11-19_1.MP4`

## 1. Purpose

Replace the current AssemblyAI and Anthropic processing paths with a fully local workflow that produces:

1. a timestamped Traditional Chinese transcript;
2. anonymous speaker labels derived through local diarization;
3. canonical transcript JSON and deterministic Markdown;
4. an evidence-linked Traditional Chinese financial report generated by a local language model.

No media, audio, transcript segment, prompt, report content, or runtime metadata may be sent to a cloud inference service. Network access is allowed only during an explicit model-download/setup command. Normal `probe`, `transcribe`, `report`, and `run` commands must operate with network access disabled and must fail if they attempt external communication.

## 2. User-approved constraints

- Processing must not use cloud transcription, translation, diarization, reporting, or summarization services.
- Additional open-source model downloads are allowed when inference remains entirely on the Mac.
- Speaker diarization is required; the initial implementation must stop rather than silently omit speakers when diarization fails.
- A separate local Python 3.12 environment is allowed for diarization compatibility.
- Quality is preferred over speed.
- Required deliverables are the Traditional Chinese transcript and evidence-grounded report.
- The existing source MP4 must never be modified or uploaded.

## 3. Target hardware and available local assets

The target machine is an Apple M4 Pro with 48 GiB unified memory and Metal 4 support.

Available tooling:

- `ffmpeg` and `ffprobe` from Homebrew;
- `mlx_whisper` installed globally;
- a cached `mlx-community/whisper-large-v3-turbo` snapshot;
- Ollama installed, but its only current model is `glm-5.2:cloud`, which is prohibited and must never be selected.

The implementation must use MLX-native inference for ASR and reporting so Apple Silicon is used efficiently; PyTorch is confined to the isolated diarization worker.

## 4. Architecture

### 4.1 Python 3.13 coordinator

The existing `vcc` CLI and provider-neutral domain/pipeline boundaries remain the coordinator. The CLI owns argument parsing and exit codes; the pipeline owns orchestration; worker adapters own local model execution.

Production wiring must no longer import, construct, or require AssemblyAI or Anthropic clients. Cloud SDK dependencies and credential configuration are removed from the default package. The existing `Transcriber` and `Reporter` protocols remain, with local implementations replacing the cloud adapters.

### 4.2 Media layer

The accepted media behavior remains:

1. `ffprobe` validates the exact source path and reports streams.
2. `ffmpeg` maps only the selected audio stream.
3. AAC audio is stream-copied into M4A when possible.
4. Video frames are never decoded for transcription.
5. The source MP4 is never an inference artifact.

### 4.3 Local ASR adapter

Add a `LocalWhisperTranscriber` adapter that invokes a pinned `mlx_whisper` executable through an argument array.

Default model:

- `mlx-community/whisper-large-v3-turbo`, resolved to a local snapshot directory before processing.

Required invocation properties:

- task: transcription, not English translation;
- language: Mandarin/Chinese (`zh`);
- word timestamps enabled;
- deterministic decoding (`temperature=0`);
- JSON output;
- submit the full extracted audio in one local ASR invocation; chunk only if the worker reports a hard local limit, using deterministic overlap and de-duplication;
- no model download or remote lookup during processing.

The adapter retains the raw MLX Whisper JSON and maps words/segments into provider-neutral intermediate ASR models. It must reject malformed output, missing timestamps, empty speech output for non-silent media, or references outside the probed media duration.

### 4.4 Local diarization worker

Diarization runs as a subprocess in a managed Python 3.12 environment, isolated from the Python 3.13 CLI.

Default model family:

- a pinned local snapshot of `pyannote/speaker-diarization-community-1`; setup must fail clearly if that exact model cannot be downloaded or loaded rather than silently substituting another model.

The setup command may use a Hugging Face token solely to download a gated model snapshot after the user accepts its terms. Runtime commands must resolve the snapshot locally and must not require the token or contact Hugging Face.

The worker receives only:

- the local extracted audio path;
- optional minimum/maximum speaker bounds;
- the local model snapshot path;
- output JSON path.

It returns ordered intervals containing start seconds, end seconds, and chunk-local anonymous speaker identifiers. It performs no speaker identity recognition.

Device policy:

1. use Apple Metal/MPS when supported by the pinned stack;
2. otherwise run locally on CPU;
3. never fall back to a remote endpoint.

### 4.5 ASR/diarization merge

A pure merger combines Whisper words with diarization intervals.

For each word:

1. calculate overlap with every diarization interval;
2. assign the word to the interval with the greatest positive overlap;
3. when no interval overlaps, use the nearest interval only when its boundary is within 0.25 seconds of the word midpoint;
4. if no interval is close enough, mark it as temporarily unassigned rather than guessing a speaker.

Segments are then rebuilt by joining adjacent words while:

- the speaker label remains the same;
- the silence gap stays at or below 1.0 second;
- the resulting segment duration stays at or below 30 seconds.

Diarization speaker identifiers are mapped deterministically by first chronological appearance to `講者 A`, `講者 B`, and so on. The system never assigns real names.

An unresolved-word ratio above 5% of non-silence words is a local-processing failure, because speaker separation is required in the approved scope.

### 4.6 Canonical transcript

The existing canonical transcript contract remains authoritative. Each segment stores:

- stable deterministic segment ID;
- start/end seconds;
- raw Whisper text;
- conservatively normalized Traditional Chinese text;
- anonymous speaker label;
- word timing and confidence where available;
- original source media metadata;
- local model identifiers and revisions in run metadata, not in display prose.

Artifact order remains:

1. raw local ASR output;
2. raw local diarization output;
3. canonical transcript JSON;
4. transcript Markdown.

### 4.7 Local report adapter

Add a `LocalQwenReporter` adapter using direct MLX inference rather than a cloud-capable endpoint.

Default model capability:

- `mlx-community/Qwen3-30B-A3B-Instruct-2507-4bit`, pinned to an exact local snapshot revision;
- model identity is configurable only as a verified local snapshot path;
- setup validates the configured snapshot and records its exact revision/checksum.

The report worker receives structured transcript segments only. It runs with:

- deterministic decoding (`temperature=0`);
- a maximum 32,768-token input budget per map/reduce call;
- a maximum 8,192 generated tokens per call;
- chronological groups of at most 30 transcript segments;
- a JSON-only prompt contract matching the existing structured report models;
- no tools, browsing, retrieval, or network access.

Because local generation does not provide Anthropic-style server-enforced structured outputs, the adapter must:

1. request exactly one JSON object;
2. parse and validate it with Pydantic;
3. retry locally with a compact schema-error repair prompt when parsing fails;
4. stop after the initial generation plus at most two local schema-repair attempts;
5. never weaken grounding validation or accept free-form Markdown.

Long transcripts use chronological map/reduce. Every mapped point retains canonical source segment IDs, and reduction may retain only evidence IDs that appeared in map results. Existing grounding code rejects unknown IDs, empty evidence, invalid sections, out-of-range evidence, and missing `講者觀點` labels.

### 4.8 Offline enforcement

Processing commands must set and verify offline mode before starting workers:

- `HF_HUB_OFFLINE=1`;
- `TRANSFORMERS_OFFLINE=1`;
- local-files-only model resolution;
- no remote URL accepted as a runtime model value;
- no `:cloud` model identifier accepted;
- no AssemblyAI or Anthropic credentials read or required.

Workers receive local file paths and JSON through subprocess boundaries. Tests install socket/HTTP sentinels that fail on external connection attempts.

The explicit setup command is the only code path allowed to download models. It must display model name, revision, expected disk use, and license/terms before downloading.

## 5. CLI behavior

The user-facing command remains:

```bash
uv run vcc run "視野環球財經robots_07-19-2026 22-11-19_1.MP4"
```

Commands:

- `vcc probe <video>`: unchanged and fully local.
- `vcc setup-local-models`: downloads/pins required models and creates the Python 3.12 diarization environment.
- `vcc transcribe <video>`: local MLX Whisper + local diarization + transcript artifacts.
- `vcc report <transcript>`: local Qwen report generation + grounding + report artifacts.
- `vcc run <video>`: complete fully local pipeline.

New configuration values are paths/revisions rather than cloud credentials:

- local Whisper executable and model snapshot;
- diarization environment executable and model snapshot;
- local Qwen environment/model snapshot;
- offline enforcement flag, enabled by default and not disableable in production commands;
- word-to-speaker overlap/tolerance thresholds;
- local report context and generation limits.

Cloud API-key fields, cloud provider model settings, and cloud runtime dependencies are removed.

## 6. Storage, identity, and resume

Cache identity includes:

- source SHA-256;
- processing language;
- speaker bounds;
- Whisper snapshot revision/checksum and decoding settings;
- diarization snapshot revision/checksum and merge thresholds;
- Qwen snapshot revision/checksum and generation settings;
- normalization and prompt schema versions.

Manifest steps become:

1. `probe`;
2. `extract`;
3. `asr`;
4. `diarize`;
5. `merge_transcript`;
6. `report_map`/`report_reduce` or a single `report` step;
7. `cleanup`.

A completed expensive local step is reusable only when every required artifact exists and matches its checksum. Corrupt or incompatible state fails with repair/`--force` guidance instead of silently recomputing.

Default successful cleanup removes extracted audio unless `--keep-audio` is set. Raw ASR/diarization output, canonical JSON, Markdown, manifests, and run metadata remain.

## 7. Error handling

Add a typed `LocalModelError` category mapped to exit code 10 for:

- missing/incomplete model snapshot;
- incompatible local worker environment;
- worker crash or timeout;
- local out-of-memory failure;
- malformed worker output after bounded retries;
- diarization coverage below the required threshold.

Other mappings remain:

- media failures for ffmpeg/ffprobe/audio problems;
- configuration failures for invalid paths/settings or prohibited remote/cloud model values;
- grounding failures for unsupported report evidence;
- filesystem failures for corrupt/missing resume artifacts;
- interrupted exit 130 for Ctrl-C.

The system must never respond to a local failure by selecting a cloud provider.

## 8. Testing

### 8.1 Unit tests

- MLX Whisper JSON parsing and timing validation;
- diarization JSON parsing and interval validation;
- word-to-speaker overlap, nearest-tolerance fallback, unresolved ratio, and stable labels;
- local Qwen JSON parsing, bounded repair retries, and evidence preservation;
- local model path/revision validation;
- cloud identifier and remote URL rejection;
- external socket/HTTP sentinels;
- resume identity and checksum behavior;
- error/exit-code mapping and secret-free logs.

### 8.2 Owned fixtures

Add repository-owned synthetic two-speaker speech generated from licensed/local text-to-speech voices. The fixture must contain known alternating speaker turns and must not include source-program content, personal data, or copyrighted speech.

Mocked worker JSON remains the default unit/integration-test input so routine tests require no model execution.

### 8.3 Opt-in local-model tests

Mark model-heavy tests explicitly, for example `pytest -m local_models`. They require downloaded snapshots but no network and no paid calls.

The test harness sets offline environment flags and fails on external connection attempts.

### 8.4 Progressive acceptance

1. Create a 30–60 second audio-only excerpt from the target video.
2. Run the complete local pipeline with networking disabled.
3. Verify ordered in-range timestamps, anonymous speakers, readable Traditional Chinese, canonical anchors, valid evidence links, and no external connections.
4. Rerun with `--resume` and verify ASR, diarization, and reporting are skipped when state is compatible.
5. Only then process the full 34:20 source.
6. Compare five sampled timestamps with playback and record uncertainty without rewriting unsupported content.

## 9. Migration

1. Add local model configuration and setup command behind tests.
2. Add local ASR worker/adapter.
3. Add isolated diarization worker and deterministic merger.
4. Add local Qwen worker/adapter.
5. Rewire production factories to local adapters.
6. Remove cloud credentials, cloud provider defaults, and cloud SDK dependencies.
7. Retire cloud-specific tests and replace them with local worker/network-prohibition tests.
8. Update README, `.env.example`, output metadata, privacy documentation, and OpenSpec artifacts.
9. Run short-excerpt acceptance offline before the full video.

Existing canonical transcript/report fields and Markdown headings remain compatible. Local model provenance is added only to run metadata. The manifest schema is incremented to version 2; all version-1 cloud-era manifests are rejected as incompatible rather than reused.

## 10. Security and privacy guarantees

- Runtime inference is on-device only.
- No source media, extracted audio, transcript, report prompt, or report output leaves the Mac.
- Model downloads are explicit and separate from media processing.
- Runtime model configuration accepts only verified local paths.
- Cloud-backed Ollama identifiers such as `glm-5.2:cloud` are rejected.
- Raw local outputs can contain sensitive speech and follow the same local retention/cleanup documentation as canonical artifacts.
- Logs contain model names, revisions, timings, and local paths but not transcript content by default.

## 11. Non-goals

- Speaker identity recognition.
- External fact-checking or market-data retrieval.
- Cloud fallback.
- Web UI or background service.
- Real-time streaming transcription.
- English translation in the initial local migration.
- Automatic continuation without required diarization.

## 12. Acceptance criteria

The design is implemented successfully when:

1. all default tests pass without network access or downloaded model execution;
2. model-heavy tests pass with networking disabled after setup;
3. the short excerpt produces valid local transcript/report artifacts;
4. monitoring confirms no external connection attempt during processing;
5. compatible resume performs no duplicate ASR, diarization, or report inference;
6. the full video produces complete transcript/report JSON and Markdown using only local models;
7. five manually sampled timestamps are plausible and any ASR uncertainty is recorded;
8. no cloud credential or cloud runtime dependency is required.
