# YouTube 影片工作區設計訪談

開始日期：2026-10-03。更新日期：2026-10-04。狀態：Q1–Q18 已確認；完整規格可作實作依據。

## 使用者已明確提出的需求

- 提供操作介面，每次接受一支 YouTube 影片網址（Q10 已確認）。
- 列出影片實際可用畫質，每次選一種下載，附加使用者選定語系的字幕（Q11 已確認）。
- 下載成品使用可切換字幕軌，支援的播放器可切換或關閉字幕（Q3 已確認）。
- 提供獨立的「附加原文字幕」開關；關閉時成品只附選定語系字幕（Q12 使用者修正後已確認）。
- 目標字幕語系每次單選，是否附加原文由獨立開關控制（Q13 已確認）。
- 字幕翻譯與 Agent 問答共用設定檔中的 Gemini API key（Q6 已確認）。
- 金鑰由專案根目錄 `.env` 的 `GEMINI_API_KEY` 讀取，需新增自動載入功能（Q17 已確認）。
- 未自行匯入字幕時，依序使用 YouTube 原語言人工字幕、自動字幕、本機語音辨識（Q4 已確認）。
- 提供與 agent 互動的區塊，詢問影片內容與相關知識。
- 問答涵蓋影片內容與背景解釋；影片內容附時間戳引用，模型補充知識另外標示（Q5 已確認）。
- 支援「更換字幕」：播放時切換語言，並可匯入自己的 SRT／VTT 字幕（Q2 已確認）。
- 播放字幕與問答依據分開選擇；匯入修正版後，可明確選擇「設為問答依據」（Q7 已確認）。
- 更換問答依據時開新對話，保留舊對話與其對應字幕版本（Q8 已確認）。
- 第一版以字幕／逐字稿作為影片依據，不加入影片畫面理解（Q9 已確認）。
- 來源無法在瀏覽器直接播放時，在本機另製作相容預覽，成品保留所選畫質（Q14 已確認）。
- 成品保留來源影音串流，相容時優先 MP4，否則使用 MKV，匯出前顯示格式（Q15 已確認）。
- 自動保存影片、字幕版本及對話至本機影片庫，重開後可續看續問，直到手動刪除（Q16 已確認）。

## 訪談紀錄

### Q1：使用情境與運行型態

選項：A 本機瀏覽器介面；B 原生桌面程式；C 多人網站。

建議 A：介面在瀏覽器操作，下載與媒體處理在本機執行，可沿用現有 Python 工具；
Gemini 翻譯仍需連線至雲端。

答案：使用者回覆「A」，已確認採用本機瀏覽器介面。

決策記錄：[ADR 0001](../adr/0001-local-browser-interface.md)。前端框架、服務啟動方式、
檔案目錄與歷史保存方式未隨本題一併決定。

### Q2：更換字幕的操作範圍

以下選項可複選：

- A：播放時切換已取得或產生的不同語言字幕。
- B：匯入自己的 SRT／VTT 字幕檔，作為影片的替代字幕。
- C：在介面直接修改字幕文字與時間軸。

建議 A + B：提供語言切換與匯入修正版字幕。

答案：使用者回覆「A+B」，已確認播放切換與字幕匯入；介面內直接編輯文字／時間軸
不納入本次範圍。字幕變更對問答依據的影響已於 Q7 確認；Q8 確認保留舊對話所用
的字幕版本，未用於對話的字幕保留／刪除規則仍待設計。

可驗收行為：同一影片有多種語言字幕時可選擇顯示其中一種；匯入有效的 SRT 或 VTT
後，可選用該字幕播放。兩種匯入格式都須驗證，不能只支援其中之一。

### Q3：下載成品如何附加字幕

- A：可切換字幕軌，字幕放進影片檔，在支援的播放器中可切換或關閉。
- B：固定燒錄，字幕成為畫面的一部分，更換字幕需重新輸出影片。
- C：同時提供上述兩種輸出方式。

建議 A：與已確認的字幕切換需求一致。影片容器、播放器相容性、多字幕軌數量
與字幕檔獨立匯出功能需在選定方式後釐清，未隨本題默認。

答案：使用者回覆「A」，已確認下載成品使用可切換字幕軌。

可驗收行為：匯出的影片包含字幕軌，並能在約定支援的播放器中顯示與關閉；
包含多軌時可切換。驗證須同時檢查成品字幕串流與實際播放；支援的容器／播放器
清單尚待決定，不能把本機網頁可切換等同於下載檔已正確附加字幕。

### Q4：字幕來源策略

此題針對未自行匯入字幕的情境；使用者已選用的匯入字幕不能被自動流程默默取代。

- A：優先取得 YouTube 原語言人工字幕，其次自動字幕；都沒有時才在本機辨識語音。
- B：每次都從影片音訊在本機辨識，建立字幕。
- C：僅使用 YouTube 字幕或使用者匯入；無可用字幕時提示使用者匯入。

取得原文後，依選定語言需要使用 Gemini 翻譯。建議 A，以重用既有字幕並涵蓋
無字幕影片。

答案：使用者回覆「A」，已確認上述取得順序，缺少所選語言時按需使用 Gemini 翻譯。
辨識失敗、語言判定、譯文已存在時的重用規則及原文保留方式仍需後續定義。

可驗收行為：在原語言人工字幕可用時選用人工字幕；僅自動字幕可用時選用自動字幕；
兩者都不存在時才啟動本機辨識。三種情境各有對應測試，已有可用字幕時不重做辨識。
字幕清單取得失敗與確認字幕不存在是不同情境，前者的重試／提示行為尚待設計。

### Q5：影片問答的知識範圍

以影片提到「通膨」為例：

- A：僅依影片內容回答，說明影片如何談通膨；影片未提及的資訊明確表示沒有依據。
- B：影片內容加背景解釋，可補充通膨定義與例子；清楚區分影片內容與模型補充知識。
- C：包含 B，再提供網路查詢，能查最新資料並附外部來源連結。

建議 B，符合「影片內的相關知識」與延伸學習需求。影片相關回答建議附時間戳引用，
補充知識不冒充影片原話。

答案：使用者回覆「B」，已確認影片內容加背景解釋，影片內容附時間戳引用，補充知識
另外標示。本次不加入即時網路查詢；問答服務已於 Q6 確認為 Gemini，Q9 確認第一版
不加入畫面理解，引用跳轉仍待確認。

可驗收行為：詢問影片提到的概念時，答案能分清影片說法與延伸解釋，影片說法帶有
對應片段的時間戳；影片未提到的背景資訊不得標成影片原話。混合兩類內容的答案也須
清楚標示來源性質，不能以單一影片引用涵蓋整段外部知識。來源標示、時間定位與抽樣
語意核對需分別驗證；模型補充知識不宣稱已經即時查證。

### Q6：問答模型服務

- A：使用 Gemini，字幕翻譯與問答共用設定檔中的 Gemini API key。
- B：使用 Claude，字幕翻譯使用 Gemini，問答另設 Anthropic API key。

建議 A，以單一服務憑證支援這次新增的翻譯與問答需求。具體模型名稱與翻譯／問答
是否各別設定模型，留待設定契約設計時決定；此題不更動既有 CLI 報告的服務設定。

答案：使用者回覆「A」，已確認字幕翻譯與 Agent 問答共用設定檔中的 Gemini API key。

可驗收行為：僅設定 Gemini 憑證即可使用新介面的翻譯與問答，兩者不要求 Anthropic
憑證。驗證涵蓋共用憑證的設定載入與兩個服務邊界；設定檔位置、格式及具體模型尚待決定。

### Q7：字幕變更與問答依據

情境：已經開始問答，使用者切換顯示語言，或匯入修正了原字幕錯字的新檔案。

- A：由使用者指定問答依據。切換字幕語言只影響播放；匯入修正版後，可另選
  「設為問答依據」。
- B：問答自動跟隨目前播放的字幕，每次切換語言或選用匯入字幕時，問答依據一併改變。
- C：固定使用最初取得的原文字幕或轉錄；後續新增字幕僅供播放。

建議 A，讓修正版可以改善問答內容，同時避免顯示語言切換反覆改變問答基準。
此題決定來源選取行為；依據變更後的舊對話、引用、快取與進行中請求如何處理，
需在後續明確定義。

答案：使用者回覆「A」，已確認播放字幕與問答依據分開選擇；匯入修正版後，使用者
可選擇「設為問答依據」。記錄於 [ADR 0002](../adr/0002-separate-playback-and-qa-source.md)。

可驗收行為：將顯示字幕從英文切換為繁中，問答來源仍維持原先選擇；匯入修正版並
僅選用播放時，也不自動改變問答來源。明確執行「設為問答依據」後，後續以該依據
提出的新問題應使用修正版內容，並能在介面辨識目前採用的依據。更換後既有對話的
行為由 Q8 決定。

### Q8：更換問答依據後的對話

情境：使用者已有一串問答，接著將修正版字幕設為問答依據。

- A：保留舊對話及其對應字幕版本，改用新依據開新對話。
- B：在同一串對話延續，標示依據切換點；舊答案仍保留原依據的引用。

建議 A，使舊答案可追溯原文，新對話也不沿用舊字幕產生的回答作為上下文。
對話跨重啟保存已於 Q16 確認；刪除與進行中請求的處理方式仍待設計。

答案：使用者回覆「A」，已確認更換問答依據時另開新對話，並保留舊對話與其
對應字幕版本。此決定已補入 [ADR 0002](../adr/0002-separate-playback-and-qa-source.md)。

可驗收行為：以字幕版本 V1 建立問答後，將修正版 V2 設為問答依據，新對話的問題
使用 V2，且上下文不帶入 V1 的舊回答；舊對話仍可查看，其引用仍對應 V1 原文與時間。
即使 V1、V2 檔名或片段 ID 相同，舊引用也不能改指 V2。驗證須包含修正文字及時間
的字幕樣本，並確認新對話的實際請求沒有夾帶舊回答。

### Q9：影片畫面理解

情境：影片中的圖表、投影片或操作畫面，可能包含字幕沒有提到的資訊。

- A：僅使用選定的字幕／逐字稿問答；無法由文字得知的畫面內容，明確表示缺少依據。
- B：除了字幕問答，提問時可手動附上當前影片畫面，將該畫面連同問題與文字內容
  送給 Gemini 解釋。

建議 A 作為第一版，先完成已確認的字幕問答流程。B 適合需要解讀圖表或操作畫面的
使用情境；選擇 B 後仍需定義畫面來源、引用、保存及模型能力驗證。兩者都維持 Q5
已確認的背景知識解釋範圍，不能將缺乏影片依據的推測當成影片內容。

答案：使用者回覆「A」，已確認第一版使用選定字幕／逐字稿作為影片依據，保留
背景解釋，不提供影片截圖或其他畫面理解功能。

可驗收行為：問答使用所選文字依據；若問題涉及僅出現在畫面的圖表數字或操作細節，
而文字依據沒有資訊，應表明缺少依據，不能宣稱看過畫面或捏造視覺細節。仍可另以
「補充知識」解釋相關概念。驗證包含文字可答、畫面資訊缺失與一般背景解釋三類問題。

### Q10：YouTube 匯入範圍

- A：每次輸入一支影片網址，個別選畫質、處理字幕與問答。
- B：可一次貼上多支影片網址，逐支處理。
- C：包含 B，另可匯入播放清單並勾選要處理的影片。

建議 A 作為第一版，先完整串接單支影片的下載、字幕與問答流程。單次匯入範圍
不等於只能保存一支影片；Q16 已確認影片歷史跨次保存，同時執行的任務數另待確認。

答案：使用者回覆「A」，已確認第一版每次匯入一支影片，個別選畫質、處理字幕與問答。

可驗收行為：一次匯入只建立所指定影片的處理工作；網址帶有播放清單資訊時，不能
自動擴展成整份清單下載。純播放清單或多網址輸入須提示本版接受單支影片網址。
Q16 已確認保存多支影片的本機影片庫；再次匯入同一影片的重用規則仍待設計。

### Q11：下載畫質的選擇方式

- A：列出該影片實際可用的畫質，每次選一種下載。
- B：列出該影片實際可用的畫質，可同時勾選多種，輸出多個畫質版本。

建議 A，符合可選不同畫質的需求，且每次下載的成品與進度較容易理解。選項依來源
實際提供的畫質，例如 720p、1080p 或 4K；不把範例當成每支影片都具有的選項。
此題只決定一次輸出的畫質數量；預設畫質、幀率、編碼、檔案大小顯示與無法取得
所選畫質時的行為仍待設計。

答案：使用者回覆「A」，已確認列出來源實際可用畫質，每次選一種下載。

可驗收行為：僅有 720p 與 1080p 的來源，不能顯示可選的 4K；選 720p 時產生一份
對應畫質成品，不另外下載其他畫質版本。來源畫質選項與結果須核對，不以範例清單
冒充每支影片的實際可用畫質。之後更換畫質再匯出的重用與檔名規則仍待設計。

### Q12：下載成品包含的字幕軌

原提案將「是否附加原文」與「目標語系數量」組合成互斥選項；使用者要求改成
可以選擇要不要原文，不需要時只用選定語系。

答案：已確認新增獨立的「附加原文字幕」開關。開啟時成品包含原文及選定語系字幕，
關閉時成品只包含選定語系字幕。此開關只控制匯出內容，不刪除翻譯來源或舊問答
所需的字幕版本。開關預設值仍未確認；目標語系單選已於 Q13 確認。

可驗收行為：以英文原文、繁中目標字幕測試，開啟時成品有英文與繁中兩軌，關閉時
只有繁中一軌。兩種匯出都不改變目前播放字幕、問答依據或舊引用。原文與目標語言
相同時的去重、同語系修正版選用與字幕未完成時的匯出行為仍需在設計中明確化。

### Q13：目標字幕語系數量

- A：每次選一個目標語系，例如繁中；是否附加原文由獨立開關控制。
- B：可同時選多個目標語系，例如繁中與日文；是否附加原文同樣由獨立開關控制。

建議 A 作為第一版，先完成一個目標語系的翻譯與匯出。此題只決定目標語系數量，
不重新詢問 Q12 已確認的原文開關。

答案：使用者回覆「A」，已確認每次選一個目標語系，並保留獨立的原文開關。

可驗收行為：選擇繁中後改選日文，這次輸出目標僅為日文，不能同時自動新增繁中
翻譯任務；原文開關開啟或關閉都不改變目標語系。以不同原文／目標語言測試時，
成品分別包含「原文＋一個目標」或「只有一個目標」。原文與目標相同的去重待設計。

### Q14：瀏覽器無法直接播放來源時的處理

官方文件顯示媒體能否播放與編碼、容器及播放環境有關，不能只憑副檔名保證相容。
依據：[MDN video codecs](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Formats/Video_codecs)。

- A：保留所選畫質的下載來源，必要時另在本機製作瀏覽器可播放的預覽版本，
  讓使用者仍能在網頁內觀看與問答；會增加處理時間及磁碟使用。
- B：無法直接播放時，改由外部播放器觀看下載檔；網頁保留字幕與問答功能，
  不額外製作預覽影片。

建議 A，以維持本機網頁內的觀看流程。預覽畫質、產生時機、
取消／失敗處理、快取與支援瀏覽器清單需在決定方向後明確化。成品匯出容器已於 Q15 確認，
不能以相容預覽替換使用者指定的下載畫質。

答案：使用者於 2026-10-04 回覆「A」，已確認必要時在本機另製作相容預覽，維持
網頁內播放。記錄於 [ADR 0003](../adr/0003-separate-preview-and-export.md)。

可驗收行為：可直接播放的來源能在網頁觀看；無法直接播放的來源可由額外預覽提供
播放與字幕切換，而成品仍使用使用者選定的下載畫質。預覽與字幕時間須對齊，產生
預覽不得覆寫下載來源或成品。驗證須包含實際瀏覽器播放、字幕同步及原成品完整性。

### Q15：下載成品的格式策略

- A：保留來源影音串流；相容時優先 MP4，否則使用 MKV，並在匯出前顯示實際格式。
  不為了固定副檔名重新壓縮影音。
- B：固定輸出 MP4；需要時將影音轉成相容編碼，接受額外處理時間及可能的重新壓縮損失。

建議 A，讓成品保留選定來源的影音品質，網頁播放則由 Q14 的相容預覽支援。
FFmpeg stream copy 可避免影音重新編碼，但容器仍須相容；字幕需依容器轉換格式。
依據：[FFmpeg Streamcopy](https://ffmpeg.org/ffmpeg.html#Streamcopy)及
[相容性查證](media-compatibility-notes.md)。

支援的編碼／容器組合與播放器須驗收，不能僅以副檔名宣稱通用相容。
若兩種容器都無法封裝，錯誤與後續操作需明確呈現，不能靜默降畫質或改用預覽成品。

答案：使用者回覆「A」，已確認相容時優先 MP4，否則使用 MKV，匯出前顯示格式，
並保留來源影音串流。決策補入 [ADR 0003](../adr/0003-separate-preview-and-export.md)。

可驗收行為：以相容與不相容 MP4 的來源組合分別驗證 MP4／MKV 選擇；匯出格式與
副檔名一致，影音未重新編碼，且所選字幕軌實際存在。驗證需核對來源／成品影音
串流及字幕，不以檔案副檔名或匯出命令成功作為唯一依據。必要的字幕格式轉換不代表
允許影音轉碼；格式封裝失敗不可降畫質重試。
